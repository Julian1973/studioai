# Character role integrity — implementation 1.0

Follow-up: [Compact Seedance execution 1.0](COMPACT-SEEDANCE-EXECUTION.md) adds
source-derived visible cast, shorter provider emission and protected-audio budget
checks. Its qualification record supersedes the earlier draft prompt length;
neither draft is a submitted or approved render.

The shared Prompt Director now resolves character identities from the **actual upload
manifest** and compiles the reference tag beside names in labelled visual action,
camera, performance, setting and end-state fields. Spoken-action lines, quoted
dialogue and dedicated audio sections remain unchanged. This is a compiler and
explicit-record check, not automatic face recognition or proof of a good render.

## Completed in this pass

- Native manifest records carry identity-registry name, source hash and distinguishing
  features. Project manifest records carry their project-library identity binding.
- The shared role matrix records IDs, identity files/tags/hashes, traits, acting,
  state transitions, per-view visibility, exact dialogue ownership and audio binding.
- Explicit tag conflicts, mismatched identity files, unauthorised shared identity
  sources, literal exclusive-action transfers, and structured dialogue/event-owner
  changes block before Prompt Director review. A prose shared-identity exception
  alone is insufficient: it must link to a separately authorised source record.
- Current actual bindings are checked again when verifying the Prompt Director seal.
  Native absolute files are rehashed; project relative files retain the workspace
  artifact checks. The matrix is included in sealed reports and returned-review data.
- The native and project request paths retain durable blocked reports. Failure to
  persist native report evidence prevents sealing. Source slots from earlier stages
  are excluded from the native reviewer authorities; actual upload slots govern.
- Canonical traits are concise. Local shot actions are not promoted to global canon.
- Visual character names newly added by a Prompt Director repair are rebound to the
  actual upload manifest before the second review and sealing. This leaves protected
  dialogue and dedicated Audio1 instructions unchanged.
- WATCH now separates the render-linked Prompt Lab contract from working specialist
  direction. Old working overrides and scene-package prose cannot be labelled as the
  sent prompt. Evidence refreshes without rebuilding the video player; an unlinked
  pending video edit cannot inherit the original take's prompt attribution.
- 271 focused tests passed; network is disabled in role/route qualification. Older
  fixtures with no image files were supplied real synthetic hashed references.
- Follow-up verification: 163 focused UI, role, Prompt Director and native/route
  tests passed after adding WATCH prompt attribution and rebinding reviewer-added
  visual names. JavaScript syntax passed. These are local code/fixture checks, not
  a refreshed live browser or a new provider generation.

## Qualification boundaries and remaining work

- Native WATCH and project WATCH use the shared role resolver and seal. Direct native
  targeted edits retain the existing bounded, hash-bound source-video review. That
  mode is explicitly **not qualified for new canonical identity replacement**; it
  does not invent image tags for characters visible only in a source video.
- New plans may author characterRoles and characterRoleEvents. Existing plans derive
  roles from acting, state and dialogue, with an explicit warning when no exclusive
  action contract exists. Literal checks do not claim semantic paraphrase detection.
- Visual-name tagging currently targets labelled visual fields in the native prompt
  format. Project structured coverage is provided to the reviewer with the resolved
  matrix; it is not claimed to have the complete new Seedance Prompt Skill format.
- The complete Prompt Skill and immutable Audio1 master brief remains a separate,
  unfinished acceptance list. This change does not complete that broader brief.
- No live reviewer, generation, targeted edit, audio generation, server reload or
  Git push occurred in this pass. Existing approved media and production records
  were not rewritten. A new render still needs ordinary current workflow review
  and sealing; a passing structural test is not returned-film approval.
