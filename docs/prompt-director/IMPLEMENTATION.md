# Prompt Director 1.0.0 — implementation and qualification boundary

This is an internal WATCH request review, not a creative-success certification. No live
review model, image, voice or video provider was called to qualify this change.

## Active paths

* Crystal Bears compatibility workflow: `cb_render._sealed_envelope` reviews each exact
  execution-plan segment after compilation and before hashing/disclosure. Safe quoted
  visual corrections are applied to the segment, reviewed again, and rechecked by the
  existing Seedance syntax/firing-floor check. `_verify_envelope` refuses missing,
  blocked or stale Prompt Director evidence before submission. Existing binding and
  file-hash checks still protect authoritative amendments and approved audio.
* Project workflow: `Production.command(request)` schedules internal `prompt_review`
  using the project's direction connection. `reserve` reserves two configured text
  estimates inside the existing episode budget/job system. Completion creates the
  normal WATCH request, not another approval form. `reserve(watch)` and the worker
  immediately before `video_submit` compare the current authoritative snapshot with
  the review. The provider receives the reviewed prompt. No environment-key fallback.
* Both request interfaces display summary, camera/audio intent and an expandable
  continuity/correction report. Actual provider content remains inspectable.
* Project returned-media review retains the originating Prompt Director record in the
  render and both sampled-frame and native-video review contexts. Subsequent shot
  amendments cannot replace that original intended-state record.

## Existing structures extended

Director Card / coverage / stateChanges remain source authorities; the new ledger is a
review projection, not a second editable story. Existing reference records and order,
request envelopes, checksums, budgets, jobs, source signatures, approval state,
request evidence and media-review manifests are retained.

`studio_prompt_director` provides the shared typed review, entity state/cause ledger,
reference authority resolution, bounded quoted visual edits, re-review, snapshot seal,
and source inclusion trace. Reference scopes are emitted to the final prompt, not
merely shown in a report. Declared obsolete opening/current-state evidence blocks;
identity and environment references are restricted to their appropriate authority.
Missing pixel observations are explicitly unverified, not invented findings.

Deterministic checks reject incompatible values for the same entity/field/time and
unexplained state changes between views. They work equally for location, holder,
attachment, mechanical condition and visible marks. Semantic extraction checks the
story, camera, acting, cause/consequence and references; model interpretation remains
fallible. Extracted state values are not a visual observation of the rendered film.

Quoted dialogue and audio-related sections are protected against reviewer edits, as
are reference-tag order and all non-prompt request fields. New story events or dialogue
are not authorised repairs. Two review rounds allow a local wording repair and an
independent recheck; unresolved contradictions are retained for resolution, not
silently weakened to reach a score. The 9.5 authoring threshold is unchanged.

## Overrides and recovery

There is deliberately no blanket override of stale inputs, immutable audio, identity
or contradictory state. A director changes the authoritative scoped direction through
the existing revision workflow; a fresh request is compiled and reviewed. Creative
choices such as a hold, nonverbal overlap or offscreen action are not hard failures
merely because a reviewer prefers something else. Advisory risks do not require an
extra approval. Legacy tokens issued without this review must be refreshed. Already
running jobs retain their original request; this change does not mutate their history.

## Evidence and limitations

`before.txt`, `after.txt`, `ready-fixture.json`, and `blocked-fixture.json` are controlled
fixture demonstrations with a mocked reviewer, **not** a claim that a live model passed
the scene. The obsolete fixed-position clause is replaced; exact Audio1 wording is
preserved. The blocked example retains the contradiction and a corrective explanation.

The checks do not reconstruct 3D geometry, inspect image pixels, certify acting,
prove all meaningful entities were extracted, or guarantee no future provider reset.
They do not generate state keyframes, introduce a new SEE approval, or submit a render.
Legacy returned-media learning is available through source-bound observations and the
shared record helper; automatic native media analysis remains the existing project
route. No real provider/creative qualification or universal route claim is made.

Learning now supports a non-approval `observed` outcome and filters retrieval by project.
Julian's audio/lip-sync success was recorded against the actual render identity, labelled
as user feedback rather than assistant listening or whole-shot approval. Lessons remain
advisory; one scene does not become universal story policy.

* `test_amendment_invalidates_sealed_review`

* `test_true_audio_conflict_blocks_and_is_grounded`
* `test_obsolete_opening_blocks_but_identity_reference_is_scoped`
* `test_legacy_seal_reviews_actual_segment_and_fire_rechecks_it`
* `test_see_hear_request_render_approvals_use_one_pipeline` (chat and buttons;
  synthetic media/provider; exact reviewed prompt reaches fake submission)
* `test_prompt_director_blocks_tampered_request_before_video`
* `test_return_review_is_not_approval_or_listening`
* `test_observed_feedback_does_not_grant_approval_or_cross_projects`

No approved audio, screenplay, canon, SEE image or WATCH result was changed. No paid
render or other provider request was submitted during this implementation.
